## Repository overview

FlowSync is a course exercise repo (LIDR AI4Devs, cohort 202609-1) with two independent npm projects, both TypeScript end to end:

- `backend/` — AdonisJS 7 API (Lucid ORM on SQLite, VineJS validators, access-token auth). **It already exists and is treated as read-only for the exercise**: read it to learn the API contract, don't modify it.
- `frontend/` — React 19 + Vite 8, still the bare Vite template (`src/App.tsx`). This is where feature work happens. The course expects shadcn/ui components (copied into the repo, not installed as a dependency); it is not set up yet, and neither are a router or a formatter.

`README.md` is the exercise statement (in Spanish, generated, "no se edita a mano"). `prompts.md` is a template the student fills in with the prompts they ran. Requires **Node.js 24+** (Node 20 fails with `Unknown file extension ".ts"`).

## Commands

Backend (run from `backend/`):

```bash
npm install && cp .env.example .env && node ace generate:key   # first-time setup
node ace migration:run      # creates tmp/db.sqlite3 and regenerates database/schema.ts
npm run dev                 # node ace serve --hmr, http://localhost:3333
npm test                    # node ace test (Japa); suites: unit, functional
node ace test functional    # one suite
node ace test --files tests/functional/auth.spec.ts   # one file
node ace test --tests "test title"                    # one test by title
npm run lint                # eslint
npm run typecheck           # tsc --noEmit
npm run format              # prettier (@adonisjs/prettier-config)
```

Tests live in `tests/unit/**/*.spec.ts` and `tests/functional/**/*.spec.ts`; none exist yet. Functional suites start the HTTP server automatically (`tests/bootstrap.ts`).

Frontend (run from `frontend/`, in a separate terminal while the backend runs):

```bash
npm run dev       # http://localhost:5173
npm run build     # tsc -b && vite build (this is the type check)
npm run lint      # oxlint
```

## Backend architecture

Request flow: `start/routes.ts` → controller (`app/controllers/`) → VineJS validator (`app/validators/`) → Lucid model (`app/models/`) → transformer (`app/transformers/`) → `ctx.serialize(...)`.

- **Routes** reference controllers through the generated `#generated/controllers` barrel (`controllers.NewAccount`, etc.), not direct imports. Imports elsewhere use the `#alias/*` subpath imports defined in `package.json`.
- **Generated files**: `.adonisjs/` (controllers barrel, Tuyau typed route registry for clients, `routes.d.ts`) is regenerated by the `adonisrc.ts` init hooks when the dev server or ace runs; `database/schema.ts` is regenerated by `migration:run`. Don't edit either by hand. Models extend the generated schema classes (`User extends compose(UserSchema, withAuthFinder(hash))`). Schema changes go in a new migration, never by editing an existing one.
- **Response envelope**: `providers/api_provider.ts` adds `ctx.serialize`, which wraps payloads in `{ data: ... }`. Transformers whitelist exposed fields (`UserTransformer` returns `id, fullName, email, createdAt, updatedAt, initials`, never the password hash).
- **Auth**: the default guard is `api` (opaque access tokens stored in `auth_access_tokens`, value prefixed `oat_`). Clients send `Authorization: Bearer <token>`. A `web` session guard is configured but unused by the routes. `force_json_response_middleware` makes every response JSON, including errors.
- **CORS**: in dev, any origin is allowed with credentials (`config/cors.ts`).

### API contract (what the frontend must match)

All under `/api/v1`:

| Method & path | Auth | Body | Success response |
|---|---|---|---|
| `POST /auth/signup` | – | `{ fullName?: string \| null, email, password, passwordConfirmation }` | `{ data: { user, token } }` |
| `POST /auth/login` | – | `{ email, password }` | `{ data: { user, token } }` |
| `GET /account/profile` | Bearer | – | `{ data: user }` |
| `POST /account/logout` | Bearer | – | `{ message }` (not wrapped) |

Validation rules (`app/validators/user.ts`): email must be a valid address, ≤254 chars, and unique on signup; password must be 8–32 chars on signup; **`passwordConfirmation` is required and must equal `password`**. A validation failure returns 422 with VineJS's `{ errors: [{ field, message, rule }] }` shape (a duplicate email fails on `rule: "database.unique"`). Bad login credentials return 400 from `User.verifyCredentials`, and a missing or invalid token returns 401.

## Frontend notes

- TypeScript is strict about unused code (`noUnusedLocals`, `noUnusedParameters`, `verbatimModuleSyntax`, `erasableSyntaxOnly`), so use `import type` for types and avoid TS-only runtime syntax such as enums.
- oxlint enforces `react/rules-of-hooks` and warns on `react/only-export-components`.
- `vite.config.ts` has no dev proxy, so API calls go straight to `http://localhost:3333` (CORS already allows it).
